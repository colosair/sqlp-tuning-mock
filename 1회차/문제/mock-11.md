## 문제 11

### 문제

주문 테이블(약 90만 건)과 주문상세 테이블(약 540만 건)을 조인하는 SQL의 실행계획이다. 주문상세에는 인덱스 `주문상세_IX = (주문번호)`가 있다. 이 실행계획에 대한 설명으로 옳은 것은?

#### [아 래]

```text
| Id  | Operation                     | Name        |
|-----|-------------------------------|-------------|
|   0 | SELECT STATEMENT              |             |
|   1 |  NESTED LOOPS                 |             |
|   2 |   TABLE ACCESS FULL           | 주문         |
|   3 |   TABLE ACCESS BY INDEX ROWID | 주문상세     |
|*  4 |    INDEX RANGE SCAN           | 주문상세_IX  |
```

### 선택지

① 후행 테이블 주문상세가 드라이빙(선행) 집합이고, 주문은 각 주문상세 행마다 한 번씩 조회된다.

② 주문이 드라이빙(선행) 집합이며, 주문 한 건마다 `주문상세_IX`의 INDEX RANGE SCAN이 반복 수행되어 주문상세가 조인된다.

③ NESTED LOOPS 대신 두 테이블을 각각 정렬한 뒤 병합하는 방식이므로, `주문상세_IX`를 경유한 테이블 랜덤 액세스는 발생하지 않는다.

④ 주문상세를 한 번의 TABLE ACCESS FULL로 모두 읽어 해시 영역에 적재한 뒤, 주문을 그 해시 테이블에 탐침(probe)한다.

---

### 정답 — ②

### 왜 ②인가

NESTED LOOPS(Id 1) 아래 두 자식의 **위치**를 읽습니다.

```text
Id 1  NESTED LOOPS
Id 2   TABLE ACCESS FULL          주문        ← 먼저 오는 자식 = 드라이빙(선행)
Id 3   TABLE ACCESS BY INDEX ROWID 주문상세    ← 나중 자식 = 인너(후행)
Id 4    INDEX RANGE SCAN          주문상세_IX  ← 인너 접근 경로
```

NESTED LOOPS에서 **먼저 나열된 자식이 드라이빙(선행) 집합**입니다. 여기서는 주문이 TABLE ACCESS FULL로 한 번 훑어지고, 그 **각 행마다** 인너인 주문상세를 `주문상세_IX` INDEX RANGE SCAN으로 반복 탐색합니다. 인덱스가 `주문번호` 단일 칼럼이고 주문:주문상세가 1:N이므로, 한 주문번호에 여러 상세가 걸려 UNIQUE가 아닌 RANGE SCAN으로 나타납니다.

그래서 방향은 **주문 → 주문상세**이고, 인너 스캔은 드라이빙 건수만큼 반복됩니다. ②이 이 구조 그대로입니다.

- ①은 드라이빙/인너를 **거꾸로** 지목합니다. 먼저 나온 자식이 주문이므로 드라이빙은 주문입니다.
- ③는 이 플랜에 없는 **SORT MERGE 조인**을 끌어옵니다. 플랜에는 정렬 노드가 없고 TABLE ACCESS BY INDEX ROWID(랜덤 액세스)가 분명히 있습니다.
- ④는 이 플랜에 없는 **HASH JOIN**을 끌어옵니다. 주문상세는 TABLE ACCESS FULL이 아니라 인덱스로 접근하며, HASH 노드도 없습니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | 드라이빙/인너를 뒤집었습니다. NESTED LOOPS의 먼저 나온 자식(Id 2, 주문)이 드라이빙이며, 주문상세가 인너입니다 |
| ② | **○** | 주문(Id 2)이 드라이빙, 주문상세가 인너이며 주문 건마다 `주문상세_IX` RANGE SCAN(Id 4)이 반복됩니다 |
| ③ | ✗ | 정렬-병합 노드가 플랜에 없고, Id 3의 TABLE ACCESS BY INDEX ROWID가 랜덤 액세스를 나타냅니다. SORT MERGE는 이 플랜 밖의 개념입니다 |
| ④ | ✗ | HASH JOIN·해시 영역 적재 노드가 없고, 주문상세는 FULL이 아니라 INDEX RANGE SCAN으로 접근합니다. 이 플랜 밖의 조인 방식입니다 |

---

## ✅ 이 문제의 핵심

1. **NESTED LOOPS의 먼저 나열된 자식이 드라이빙(선행) 집합**입니다. 방향은 위→아래로 읽습니다.
2. **인너 테이블 접근은 드라이빙 건수만큼 반복**됩니다. 여기서는 `주문상세_IX` INDEX RANGE SCAN이 주문 행마다 재실행됩니다.
3. **1:N 조인 키에는 UNIQUE가 아닌 RANGE SCAN**이 나타납니다. `주문번호` 하나에 상세 여러 건이 대응하기 때문입니다.
4. **정렬 노드·해시 노드의 유무로 조인 방식을 판별**합니다. 둘 다 없으면 NL, 있으면 각각 SORT MERGE·HASH입니다.

📌 한 줄 정리: NESTED LOOPS에서 위쪽 자식 주문이 드라이빙이고, 주문 건마다 `주문상세_IX` INDEX RANGE SCAN이 반복되어 인너인 주문상세가 조인됩니다.
