## 문제 2

### 문제

주문상세 테이블(약 3,000만 건)에서 특정 배송단계에 걸린 주문 12,600건의 상태코드를 일괄 변경하는 UPDATE의 트레이스이다. 이 SQL 한 번의 수행에 대한 **버퍼 캐시 히트율(BCHR)**로 가장 적절한 것은?

#### [아 래]

```text
Call       Count  CPU Time  Elapsed Time     Disk     Query   Current      Rows
--------------------------------------------------------------------------------
Parse          1     0.011         0.013        0         0         0         0
Execute        1     6.320        22.480    50000    920000     80000     12600
Fetch          0     0.000         0.000        0         0         0         0
--------------------------------------------------------------------------------
Total          2     6.331        22.493    50000    920000     80000     12600
```

### 선택지

① 약 94.6%
② 약 95.2%
③ 약 90.5%
④ 약 95.0%

---

### 정답 — ④

### 왜 ④인가

BCHR은 **논리적 I/O 중 디스크를 거치지 않고 버퍼 캐시에서 해결한 비율**입니다. 여기서 핵심은 논리적 I/O가 **Query(consistent gets) 하나가 아니라 Query + Current(db block gets)의 합**이라는 점입니다. UPDATE는 읽기용 블록(Query)과 변경용 블록(Current)을 모두 만지므로 Current를 빼면 안 됩니다.

```text
공식   BCHR = ((Query + Current) − Disk) / (Query + Current) × 100

논리적 I/O = Query + Current = 920,000 + 80,000 = 1,000,000
물리적 I/O = Disk           =                    50,000

BCHR = (1,000,000 − 50,000) / 1,000,000 × 100
     =    950,000          / 1,000,000 × 100
     = 95.0%
```

따라서 정답은 ④(약 95.0%)입니다.

혼동 지점을 하나씩 짚습니다.

```text
① Current를 빼먹고 Query만 논리적 I/O로 봄
   (920,000 − 50,000) / 920,000 × 100 = 870,000 / 920,000 = 94.6%
   → 하위항목(Query)을 전체 논리적 I/O로 오인한 값

③ 분모에 Disk를 잘못 더함
   (1,000,000 − 50,000) / (1,000,000 + 50,000) × 100 = 950,000 / 1,050,000 = 90.5%

② Disk를 논리적 I/O에서 빼지 않고 '추가 요청'으로 분모에만 더함
   1,000,000 / (1,000,000 + 50,000) × 100 = 1,000,000 / 1,050,000 = 95.2%
```

세 오답 모두 **분자에서 Disk를 정확히 한 번 빼고 분모는 논리적 I/O만** 두는 규칙을 어긴 결과입니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | Current(80,000)를 누락해 Query(920,000)만 논리적 I/O로 삼은 값입니다. 논리적 I/O = Query + Current이므로 하위항목만 쓰면 안 됩니다 |
| ② | ✗ | Disk를 논리적 I/O에서 빼지 않고 분모에만 더한 1,000,000/1,050,000 = 95.2%입니다. 히트한 블록 수를 잘못 잡았습니다 |
| ③ | ✗ | 분모에 Disk(50,000)를 더해 950,000/1,050,000 = 90.5%로 계산한 값입니다. Disk는 분자에서 한 번만 빼면 됩니다 |
| ④ | **○** | 논리적 I/O 1,000,000(=920,000+80,000)에서 Disk 50,000을 빼 950,000/1,000,000 = 95.0%입니다 |

---

## ✅ 이 문제의 핵심

1. **논리적 I/O = Query + Current.** BCHR 계산에서 Current(db block gets)를 빠뜨리는 것이 가장 흔한 실수입니다. UPDATE·DELETE는 Current가 큽니다.
2. **공식은 ((Query+Current) − Disk) / (Query+Current) × 100.** Disk는 분자에서 딱 한 번 빼고, 분모는 논리적 I/O만 둡니다.
3. Disk를 분모에 더하거나 분자에서 안 빼면 비슷하지만 다른 값(90.5%, 95.2%)이 나와 소거가 흐트러집니다.
4. BCHR이 높다고 무조건 좋은 SQL은 아닙니다 — 불필요한 논리적 I/O 자체가 많으면 히트율이 높아도 튜닝 대상입니다.

📌 한 줄 정리: 논리적 I/O는 Query와 Current의 합이고, BCHR은 그 합에서 Disk를 한 번 빼 다시 그 합으로 나눈 값 — 여기서는 950,000/1,000,000 = 95.0%입니다.
