## 문제 17

### 문제

상수도 요금 정산 야간 배치가 `급수사용량`(약 4억 2천만 건)과 `급수전`(약 5,100만 건)을 **급수전번호로 조인**한 뒤, **지역코드별로** 사용량을 집계한다. 두 테이블은 어느 쪽도 급수전번호로 파티셔닝되어 있지 않다. 아래 병렬 실행계획에서 조인과 집계가 병렬 서버(Slave) 사이에 어떻게 분배되는지에 대한 설명으로 가장 적절한 것은?

#### [아 래]

```text
| Id  | Operation                     | Name       | TQ    |IN-OUT|
|-----|-------------------------------|------------|-------|------|
|   0 | SELECT STATEMENT              |            |       |      |
|   1 |  PX COORDINATOR               |            |       |      |
|   2 |   PX SEND QC (RANDOM)         | :TQ10003   | Q1,03 | P->S |
|   3 |    HASH GROUP BY              |            | Q1,03 | PCWP |
|   4 |     PX RECEIVE                |            | Q1,03 | PCWP |
|   5 |      PX SEND HASH             | :TQ10002   | Q1,02 | P->P |
|   6 |       HASH GROUP BY           |            | Q1,02 | PCWP |
|*  7 |        HASH JOIN              |            | Q1,02 | PCWP |
|   8 |         PX RECEIVE            |            | Q1,02 | PCWP |
|   9 |          PX SEND HASH         | :TQ10000   | Q1,00 | P->P |
|  10 |           PX BLOCK ITERATOR   |            | Q1,00 | PCWC |
|  11 |            TABLE ACCESS FULL  | 급수전     | Q1,00 | PCWP |
|  12 |         PX RECEIVE            |            | Q1,02 | PCWP |
|  13 |          PX SEND HASH         | :TQ10001   | Q1,01 | P->P |
|  14 |           PX BLOCK ITERATOR   |            | Q1,01 | PCWC |
|  15 |            TABLE ACCESS FULL  | 급수사용량 | Q1,01 | PCWP |
```

### 선택지

① 5,100만 건인 소형 급수전(Id 11)을 :TQ10000으로 병렬 서버 전체에 복제(broadcast)하고, 4억 2천만 건인 급수사용량(Id 15)은 PX BLOCK ITERATOR로 자기 블록만 읽어 재분배 없이 probe하는 broadcast 조인이다. 각 서버가 조인 결과를 이미 쥐고 있어 Id 6과 Id 3의 집계는 재분배 없이 서버 로컬로 끝난다.

② 조인 입력 급수전(Id 9)·급수사용량(Id 13)을 조인 키(급수전번호) 해시로 각각 재분배(PX SEND HASH, TQ10000·TQ10001)해 hash-hash로 조인하고, 그와 별개로 집계는 조인 뒤 부분 집계(Id 6) → 그룹 키(지역코드) 해시로 재분배(Id 5) → 최종 집계(Id 3)로, 조인 재분배와 다른 TQ에서 일어난다.

③ 급수전과 급수사용량이 급수전번호로 동일하게 파티셔닝돼 있어 Id 7 `HASH JOIN`이 대응 파티션끼리 서버 하나씩 맡아 처리하는 full 파티션 와이즈 조인이고, Id 9·13의 큐는 파티션을 서버에 배정하는 통로일 뿐 행을 옮기지 않는다. 실제 재분배는 지역코드 집계를 위한 Id 5 :TQ10002에서만 일어난다.

④ 조인은 Id 9·13의 `PX SEND HASH`로 hash-hash 재분배되는 것이 맞지만, 조인 결과가 이미 지역코드로 뭉쳐 있어 집계는 재분배 없이 한 번의 HASH GROUP BY로 끝난다. Id 5 :TQ10002는 그 결과를 QC로 올리기 전에 거치는 통로이고, Id 6과 Id 3은 같은 집계를 중복 표기한 것일 뿐 서로 다른 단계가 아니다.

---

### 정답 — ②

### 왜 ②인가

분배 방식은 **각 입력 위의 `PX SEND` 종류**와 **TQ 번호**로 읽습니다. 이 플랜에는 재분배 지점이 세 곳입니다.

```text
Id  9  PX SEND HASH :TQ10000  (Q1,00)   급수전 → 조인 키(급수전번호) 해시 재분배
Id 13  PX SEND HASH :TQ10001  (Q1,01)   급수사용량 → 조인 키 해시 재분배
Id  7  HASH JOIN    (Q1,02)             재분배된 두 입력을 hash-hash로 조인
Id  6  HASH GROUP BY (Q1,02)            조인 직후 부분(partial) 집계
Id  5  PX SEND HASH :TQ10002  (Q1,02)   그룹 키(지역코드) 해시 재분배  ← 조인과 별개
Id  3  HASH GROUP BY (Q1,03)            최종 집계
```

- **조인 재분배(hash-hash)**: 두 테이블은 급수전번호로 파티셔닝돼 있지 않으므로, 조인하려면 양쪽을 조인 키로 맞춰 재분배해야 합니다. Id 9·Id 13의 두 `PX SEND HASH`(TQ10000·TQ10001)가 급수전·급수사용량을 급수전번호 해시로 각각 재분배하고, Id 7 `HASH JOIN`(Q1,02)이 같은 버킷끼리 조인합니다.
- **집계 재분배는 조인과 별개**: 집계 키(지역코드)는 조인 키(급수전번호)와 다릅니다. 그래서 조인 결과를 바로 최종 집계할 수 없고, **조인 직후 부분 집계(Id 6)** → **지역코드 해시로 재분배(Id 5 PX SEND HASH, TQ10002)** → **최종 집계(Id 3)** 의 2단계로 풀립니다. 이 집계용 재분배는 조인용 재분배(TQ10000·10001)와 **다른 TQ(TQ10002)** 에서 일어나는 독립된 단계입니다.

```text
② hash-hash 조인 + 별도 집계 재분배 : 조인 SEND(9·13)와 집계 SEND(5)가 다른 TQ   → 플랜과 일치   ✔
① broadcast   : Id 9(:TQ10000)가 PX SEND BROADCAST여야 함 → 실제는 PX SEND HASH
③ full PWJ    : 조인 입력에 SEND가 없어야 함 → Id 9·13에 PX SEND HASH 있음(P->P)
④ 집계 1단계  : Id 5(:TQ10002)는 P->P 재분배지 QC 통로 아님(QC는 Id 2 P->S)
```

조인 입력 위에 `PX SEND HASH`가 있다는 사실이 broadcast(①)·full PWJ(③)를 배제하고, Id 5·6·3의 2단계 집계 구조가 "집계 재분배 없음/1단계"(④)를 배제합니다. 따라서 ②가 옳습니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | :TQ10000이 붙은 Id 9는 `PX SEND BROADCAST`가 아니라 `PX SEND HASH`이므로 급수전은 복제되지 않고, 급수사용량도 Id 13에서 `PX SEND HASH`로 재분배되어 "재분배 없이 읽는다"가 틀립니다. 집계 역시 Id 5에서 재분배되므로 "서버 로컬로 끝난다"도 성립하지 않습니다 |
| ② | **○** | Id 9·13의 `PX SEND HASH`(TQ10000·10001)로 두 입력을 조인 키 해시 재분배해 hash-hash 조인하고, 집계는 부분 집계(Id 6) → 지역코드 해시 재분배(Id 5, TQ10002) → 최종 집계(Id 3)로 조인과 다른 TQ에서 별개로 일어납니다 |
| ③ | ✗ | 발문이 어느 쪽도 급수전번호로 파티셔닝돼 있지 않다고 못 박았으므로 대응 파티션 조인 자체가 성립하지 않습니다. Id 9·13은 `PX SEND HASH`에 IN-OUT이 `P->P`라 파티션 배정 통로가 아니라 행을 실제로 실어 나르는 재분배이고, full 파티션 와이즈였다면 이 SEND 자체가 없어야 합니다 |
| ④ | ✗ | 앞부분의 hash-hash 재분배는 맞지만, 집계 키(지역코드)가 조인 키(급수전번호)와 달라 조인 결과는 지역코드로 뭉쳐 있지 않습니다. Id 5는 IN-OUT `P->P`의 재분배이지 QC 통로가 아니며(QC 전송은 Id 2의 `P->S`), Id 6(부분)과 Id 3(최종)은 그 SEND를 사이에 낀 서로 다른 2단계 집계입니다 — 집계 재분배 유무를 뒤바꾼 값스왑입니다 |

---

## ✅ 이 문제의 핵심

1. **파티셔닝이 없으면 조인은 hash-hash 재분배**입니다. 두 입력을 조인 키(급수전번호) 해시로 각각 재분배(Id 9·13 PX SEND HASH)해 같은 버킷끼리 조인합니다.
2. **집계 키가 조인 키와 다르면 집계 재분배가 따로 필요**합니다. 지역코드 집계는 부분 집계(Id 6) → 지역코드 재분배(Id 5) → 최종 집계(Id 3)의 독립 단계로 풀립니다.
3. **조인 재분배와 집계 재분배는 서로 다른 TQ**입니다. 조인은 TQ10000·10001, 집계는 TQ10002에서 일어나며 둘은 별개입니다.
4. **broadcast·full PWJ는 조인 입력의 SEND 종류로 배제**합니다. broadcast면 `PX SEND BROADCAST`, full PWJ면 SEND 자체가 없어야 하는데, 이 플랜의 조인 입력에는 `PX SEND HASH`가 붙어 있습니다 — 분배 방식을 뒤바꾼 값스왑 오답입니다.

📌 한 줄 정리: 급수전·급수사용량이 조인 키로 파티셔닝돼 있지 않아 Id 9·13 PX SEND HASH로 hash-hash 조인하고, 집계 키(지역코드)가 조인 키와 달라 부분 집계 → Id 5 재분배 → 최종 집계로 조인과 별개의 TQ에서 집계 재분배가 일어난다.
