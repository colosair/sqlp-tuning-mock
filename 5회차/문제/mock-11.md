## 문제 11

### 문제

정렬된 상위 N건만 뽑는 Top-N 쿼리(`ROWNUM <= N` 또는 `FETCH FIRST N ROWS ONLY`)와 부분범위 처리에 대한 설명으로 가장 적절한 것은?

### 선택지

① `ROWNUM <= N`을 걸면 옵티마이저는 언제나 결과 집합 전체를 정렬로 완성한 뒤 앞 N건을 잘라 내므로, 정렬 순서를 제공하는 인덱스가 있어도 정렬 단계는 사라지지 않는다.

② 정렬 순서를 그대로 내주는 인덱스가 있으면 `ROWNUM <= N`은 인덱스를 앞에서부터 훑다가 N번째 행을 채운 시점에 스캔을 멈추므로(부분범위 처리), 별도 정렬 오퍼레이션 없이 상위 N건만 읽고 끝난다.

③ `ORDER BY` 없이 `ROWNUM <= N`만 쓰면 먼저 조회된 아무 N건이 담기는데, 인덱스가 있으면 이때도 값 순으로 정렬된 상위 N건(Top-N)이 저절로 보장된다.

④ NL 조인 뒤에 `ROWNUM <= N`을 두면 필요한 N건을 다 채운 시점에 조인을 멈출 수 없고, 조인 대상 집합을 끝까지 소진한 뒤에야 앞 N건을 남기므로 inner 반복 횟수를 줄이는 효과가 없다.

---

### 정답 — ②

### 왜 ②인가

Top-N 쿼리의 성능은 **상위 N건을 얻으려고 전체를 정렬하느냐, 아니면 앞쪽 N건만 읽고 멈추느냐**로 갈립니다.

핵심은 **정렬 순서를 인덱스가 대신 제공하는가**입니다. `ORDER BY` 컬럼과 인덱스 정렬 순서가 일치하면, 옵티마이저는 정렬 오퍼레이션을 두지 않고 **인덱스를 앞에서부터 훑기만 하다가** `ROWNUM`이 N에 도달하는 순간 스캔을 중단(COUNT STOPKEY)합니다. 뒤쪽 방대한 데이터는 읽지 않으므로, 데이터가 아무리 많아도 **읽는 양은 앞쪽 N건 근처로 고정**됩니다. 이것이 부분범위 처리이며 ②가 이 원리를 정확히 진술합니다.

나머지는 **부분범위 중단이 작동하는 경계를 뭉갠** 진술입니다.

- ①: 인덱스가 정렬 순서를 제공하면 정렬 단계 자체가 사라집니다(STOPKEY). "언제나 전체를 정렬한 뒤 자른다"는 정렬을 인덱스로 회피하는 경우를 지워 버린 오류입니다.
- ③: `ORDER BY`가 없으면 옵티마이저는 어떤 순서로도 정렬해 줄 의무가 없어, 인덱스가 있더라도 "먼저 만난 N건"이 담길 뿐 값 순 상위 N건이 보장되지 않습니다. Top-N을 정확히 얻으려면 반드시 `ORDER BY`가 함께 있어야 합니다.
- ④: `ROWNUM` STOPKEY는 상위 로우소스 전체에 걸리므로, 드라이빙을 인덱스 순으로 읽는 NL 조인이라면 N건을 채우는 순간 조인 자체가 멈춥니다. inner 반복도 그 지점에서 끊겨 오히려 반복 횟수가 크게 줄어듭니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | 정렬 순서를 주는 인덱스가 있으면 STOPKEY로 정렬 단계가 사라집니다. "언제나 전체 정렬 후 자른다"는 인덱스 정렬 회피 경우를 지운 오류입니다 |
| ② | **○** | 정렬 순서를 주는 인덱스가 있으면 `ROWNUM <= N`은 앞에서 N건을 채운 뒤 스캔을 멈춰, 정렬 없이 상위 N건만 읽고 끝납니다 |
| ③ | ✗ | `ORDER BY`가 없으면 인덱스가 있어도 값 순 상위 N건이 보장되지 않고, 먼저 조회된 임의의 N건이 담깁니다 |
| ④ | ✗ | `ROWNUM` STOPKEY는 조인 로우소스에 걸려 N건을 채우면 조인이 멈추므로, NL의 inner 반복 횟수도 그 지점에서 줄어듭니다 |

---

## ✅ 이 문제의 핵심

1. **인덱스가 정렬 순서를 주면 Top-N은 정렬 없이 앞 N건만 읽고 멈춘다(COUNT STOPKEY).** 이것이 부분범위 처리입니다.
2. **읽는 양이 N건 근처로 고정**되므로, 뒤쪽 데이터가 아무리 많아도 비용이 커지지 않습니다.
3. **`ORDER BY`가 없으면 Top-N은 성립하지 않는다.** 인덱스가 있어도 값 순 상위 N건은 보장되지 않습니다.
4. **NL 조인에 STOPKEY가 걸리면 N건 시점에 조인이 멈춰** inner 반복 횟수까지 줄어듭니다.

📌 한 줄 정리: 정렬 순서를 제공하는 인덱스가 있으면 `ROWNUM <= N`은 앞에서 N건만 읽고 멈추는 부분범위 처리로 동작하며, "전체 정렬 후 절단"·"`ORDER BY` 없이도 Top-N 보장"·"NL 조인은 중단 불가"는 부분범위 중단의 작동 경계를 뭉갠 오해입니다.
