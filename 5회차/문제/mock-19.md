## 문제 19

### 문제

유량계측 시스템에서 유량계 'FM-720'의 누적유량 행(초기 4200)을 TX1이 한 트랜잭션 안에서 두 번 읽는데, 그 사이 TX2가 값을 4650으로 갱신하고 커밋한다(아래 타임라인). TX1을 SQL Server의 SNAPSHOT 격리수준으로 실행할 때, TX1의 두 번째 읽기 값과 그 해석으로 가장 적절한 것은? (단, TX2는 기본 READ COMMITTED이며, 비교를 위해 동일 시나리오를 다른 읽기 일관성 방식에서도 함께 따진다.)

#### [아 래]

```text
시각   TX1 (SNAPSHOT 격리)                        TX2 (READ COMMITTED)
----   -------------------------------------      -----------------------------------
t1     BEGIN TRAN
t2     SELECT 누적유량 FROM 계측
       WHERE 유량계='FM-720';   → (A)
t3                                                UPDATE 계측 SET 누적유량 = 4650
                                                  WHERE 유량계='FM-720';  COMMIT;
t4     SELECT 누적유량 FROM 계측
       WHERE 유량계='FM-720';   → (B)
t5     COMMIT

초기 누적유량 = 4200
```

### 선택지

① SNAPSHOT 격리의 TX1은 트랜잭션 시작 시점 스냅샷을 읽으므로 (A)=(B)=4200으로 반복 가능하다. 만약 오라클 기본(문장수준 읽기 일관성)이나 SQL Server 기본 READ COMMITTED였다면 (B)=4650이 되어 두 읽기가 달라진다.

② SNAPSHOT 격리의 TX1은 t2에서 (A)=4200을 읽지만, t3에 TX2가 4650으로 UPDATE하고 커밋한 뒤 t4의 두 번째 SELECT는 새 문장이라 커밋된 최신값 (B)=4650을 읽는다. 따라서 SNAPSHOT은 두 읽기 값이 갈리는 비반복 읽기(non-repeatable read)를 그대로 허용한다.

③ RCSI(READ_COMMITTED_SNAPSHOT)를 켜면 TX1의 t4 SELECT도 t1 BEGIN TRAN 시점의 행 버전을 보게 되어 (A)=(B)=4200이 되므로, t3의 4650 커밋을 무시한다는 점에서 SNAPSHOT 격리와 결과가 같아진다. 두 옵션의 차이는 스냅샷 기준이 아니라 버전 저장소 사용 여부뿐이다.

④ 오라클 MVCC는 언두 세그먼트로 읽기 일관성을 보장하되 그 기준이 문장이 아니라 트랜잭션 시작 시점이므로, TX1이 t4에서 읽는 (B)도 t1 시점 버전인 4200이 되어 SQL Server SNAPSHOT과 값이 같아진다. t3에 커밋된 4650은 TX1이 COMMIT하는 t5 이후에야 보인다.

---

### 정답 — ①

### 왜 ①인가

관건은 스냅샷의 기준 시점이 **트랜잭션 시작**이냐 **문장 시작**이냐입니다. 방식별로 (B)를 계산하면 SNAPSHOT만 4200이고 나머지는 4650으로 갈립니다.

```text
[읽는 값 — 초기 4200, TX2가 t3에 4650으로 커밋]
                             (A) t2 첫 읽기   (B) t4 둘째 읽기
  SQL Server SNAPSHOT          4200            4200   ← 트랜잭션 시작 스냅샷(반복 가능)
  SQL Server 기본 RC(잠금)     4200            4650   ← 문장마다 커밋된 최신값
  SQL Server RCSI(문장 스냅샷) 4200            4650   ← 문장 시작 스냅샷
  오라클 기본 RC(문장수준)     4200            4650   ← 문장수준 읽기 일관성

  SNAPSHOT :  (A)=(B)=4200  (유일하게 반복 가능)
  그 외    :  (A)=4200, (B)=4650  (비반복 읽기)
```

- SQL Server **SNAPSHOT** 격리는 트랜잭션 시작 시점의 행 버전을 트랜잭션 내내 봅니다. t3에서 TX2가 4650으로 커밋해도 TX1의 (B)는 여전히 스냅샷의 4200 — 두 읽기가 반복 가능합니다.
- **RCSI**와 오라클 기본 READ COMMITTED는 모두 **문장 시작** 기준입니다. 두 번째 SELECT는 새 문장이므로 그 시점에 커밋되어 있는 4650을 읽어 (B)=4650이 됩니다. 오라클 MVCC의 읽기 일관성 단위도 트랜잭션이 아니라 **문장**입니다.

①은 (A)=(B)=4200(SNAPSHOT)과, 문장수준 방식이었다면 (B)=4650이 된다는 대비를 모두 맞혔습니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | **○** | SNAPSHOT은 트랜잭션 스냅샷이라 (A)=(B)=4200으로 반복 가능하고, 문장수준(오라클 RC·SQL Server 기본 RC)이면 (B)=4650으로 달라집니다 |
| ② | ✗ | (A)=4200과 t3의 4650 커밋까지는 맞지만 결론이 반대입니다. SNAPSHOT은 t1 BEGIN TRAN 시점 스냅샷을 트랜잭션 내내 보므로 t4의 (B)도 4200이며, 비반복 읽기를 허용하는 것이 아니라 오히려 막습니다. (B)=4650은 문장수준 방식의 값을 끌어다 붙인 값스왑입니다 |
| ③ | ✗ | RCSI의 스냅샷 기준은 트랜잭션이 아니라 **문장** 시작입니다. t4의 SELECT는 새 문장이라 그 시점에 커밋돼 있는 4650을 읽어 (B)=4650이 되고, SNAPSHOT과 결과가 갈립니다. 두 옵션은 둘 다 버전 저장소를 쓰며 차이는 바로 그 기준 시점이므로, (B)=4200은 SNAPSHOT의 값과 뒤바뀐 것입니다 |
| ④ | ✗ | 오라클도 언두로 읽기 일관성을 보장한다는 앞부분은 맞지만 그 단위는 트랜잭션이 아니라 **문장**입니다. t4의 SELECT는 자기 문장 시작 시점의 SCN을 기준으로 삼아 이미 커밋된 4650을 읽으므로 (B)=4650이며, (B)=4200은 SQL Server SNAPSHOT의 값과 맞바꾼 서술입니다 |

---

## ✅ 이 문제의 핵심

1. **SQL Server SNAPSHOT 격리는 트랜잭션 시작 시점 스냅샷**을 봅니다. 중간에 커밋된 갱신을 무시해 (A)=(B)=4200으로 반복 가능합니다.
2. **RCSI는 문장 시작 스냅샷**입니다. 새 문장인 두 번째 SELECT는 커밋된 최신값 4650을 읽으므로 SNAPSHOT과 결과가 다릅니다.
3. **오라클 기본 읽기 일관성의 단위도 문장**입니다. 트랜잭션 전체가 아니라 문장 시작 시점 기준이라 (B)=4650이 됩니다.
4. 트랜잭션 스냅샷과 문장 스냅샷은 (B)의 값(4200 vs 4650)으로 갈립니다 — 어느 시점을 기준으로 스냅샷을 뜨느냐가 반복 가능성을 결정합니다.

📌 한 줄 정리: SNAPSHOT 격리만 트랜잭션 시작 스냅샷이라 (A)=(B)=4200으로 반복 가능하고, RCSI·오라클 기본 RC 같은 문장수준 일관성은 두 번째 읽기에서 커밋된 4650을 보아 (B)가 달라집니다.
