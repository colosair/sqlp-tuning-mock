## 문제 6

### 문제

차량정비 이력 테이블(약 540만 건)에는 결합 인덱스 `정비_IX = (정비소코드, 접수일자, 정비구분)`가 있다. 정비소명을 함께 얻기 위해 정비소 테이블(기본키 `정비소_PK = 정비소코드`)과 조인하는 다음 SQL의 실행계획이다.

```sql
SELECT r.정비번호, r.접수일자, r.정비구분, s.정비소명
  FROM 정비이력 r, 정비소 s
 WHERE r.정비소코드 = 'C07'
   AND r.접수일자 >= DATE '2026-06-01'
   AND r.접수일자 <  DATE '2026-07-01'
   AND r.정비구분 = '엔진'
   AND r.정비상태 = '완료'
   AND s.정비소코드 = r.정비소코드;
```

이 실행계획에 대한 설명으로 가장 적절한 것은?

```text
Id  Pid  Operation                                   ( Cost   Card   Bytes )
---------------------------------------------------------------------------
 0    -  SELECT STATEMENT                            (  268   2100  113400 )
 1    0   NESTED LOOPS                               (  268   2100  113400 )
 2    1    TABLE ACCESS BY INDEX ROWID  정비이력       (  263   2100   75600 )
 3    2     INDEX RANGE SCAN  정비_IX                 (   19   8400         )

 5    4     INDEX UNIQUE SCAN  정비소_PK              (    0      1         )
```

### 선택지

① 정비소코드·접수일자·정비구분 세 칼럼이 모두 인덱스 액세스 조건이 되어 INDEX RANGE SCAN(Id 3)의 스캔 시작~종료 지점을 함께 좁힌다.

② 정비상태='완료'는 `정비_IX`의 인덱스 필터로 INDEX RANGE SCAN(Id 3) 단계에서 걸러진 뒤 그 결과가 8,400건이 된다.

③ 선두 칼럼 정비소코드(등치)와 접수일자(범위)까지가 액세스 조건으로 스캔 범위를 정하고, 범위 칼럼 뒤에 놓인 정비구분은 스캔 범위를 좁히지 못하는 인덱스 필터로, 인덱스에 없는 정비상태는 Id 2 테이블 액세스 단계의 필터로 처리된다.

④ INDEX RANGE SCAN(Id 3)이 돌려준 8,400건이 곧 이 SQL의 최종 결과 건수이며, 이후 단계에서 건수 감소는 일어나지 않는다.

---

### 정답 — ③

### 왜 ③인가

`정비_IX`는 `(정비소코드, 접수일자, 정비구분)` 순서입니다. 결합 인덱스의 액세스 조건(스캔 시작·종료 지점을 정하는 조건)은 **선두 칼럼부터 등치로 이어지다가, 처음 만나는 범위 조건까지**입니다.

```text
정비소코드 = 'C07'        ← 선두 등치      → 액세스 조건
접수일자   범위(6월 한 달) ← 첫 범위 칼럼    → 액세스 조건 (여기서 스캔 범위 확정)
정비구분   = '엔진'        ← 범위 칼럼 '뒤'  → 인덱스 필터 (범위를 더 좁히지 못함)
정비상태   = '완료'        ← 인덱스에 없음   → 테이블 필터
```

핵심은 **범위 조건 뒤에 오는 칼럼은 액세스 조건이 될 수 없다**는 점입니다. 접수일자가 범위(`>= … AND < …`)이므로 인덱스 정렬상 정비구분='엔진'인 엔트리는 스캔 구간 안에 흩어져 있어, 정비구분으로는 스캔의 시작·종료 지점(start/stop key)을 앞당기거나 당길 수 없습니다. 그래서 정비구분은 **스캔 범위 안에서 각 인덱스 엔트리를 확인해 걸러내는 인덱스 필터**로만 작동합니다.

정비상태는 아예 `정비_IX` 구성 칼럼이 아니므로 인덱스에서 평가할 수 없습니다. ROWID로 테이블 블록을 읽어 온 **Id 2 TABLE ACCESS BY INDEX ROWID 단계에서 테이블 필터**로 걸러집니다.

```text
INDEX RANGE SCAN 정비_IX           Card 8,400   ← 액세스(정비소코드=, 접수일자 범위) + 인덱스 필터(정비구분) 통과
TABLE ACCESS BY INDEX ROWID 정비이력 Card 2,100   ← 테이블 필터(정비상태='완료') 적용 후
```

③은 액세스 조건·인덱스 필터·테이블 필터 세 층을 정확히 구분합니다. 세 칼럼을 액세스 조건으로 뭉뚱그린 ①, 정비상태를 인덱스 필터로 오해한 ②, 인덱스 반환 건수를 최종 건수로 본 ④는 이 구조와 어긋납니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | 정비구분은 범위 칼럼(접수일자) 뒤에 있어 액세스 조건이 될 수 없습니다. 액세스 조건에 끼워 넣은 것이 오류로, 스캔 시작·종료를 정하는 것은 정비소코드·접수일자까지입니다 |
| ② | ✗ | 정비상태는 `정비_IX` 구성 칼럼이 아니므로 인덱스 필터가 아니라 Id 2 테이블 액세스 단계의 필터입니다. Id 3의 8,400건은 정비상태를 걸러내기 전 값입니다 |
| ③ | **○** | 정비소코드(등치)·접수일자(범위)가 액세스 조건, 범위 뒤 정비구분은 인덱스 필터, 인덱스에 없는 정비상태는 테이블 필터 — Card가 8,400→2,100으로 줄어드는 흐름과 일치합니다 |
| ④ | ✗ | 8,400은 Id 3 인덱스 단계 Card일 뿐이며, 정비상태 테이블 필터를 거친 최종 Card는 Id 2의 2,100입니다. 테이블 액세스 단계에서 건수 감소가 분명히 일어납니다 |

---

## ✅ 이 문제의 핵심

1. **액세스 조건은 선두 칼럼 등치부터 첫 범위 칼럼까지.** 정비소코드(=)·접수일자(범위)가 INDEX RANGE SCAN 구간을 확정합니다.
2. **범위 칼럼 뒤 칼럼은 인덱스 필터.** 정비구분은 인덱스에 있어도 접수일자 범위 뒤라 스캔 범위를 좁히지 못하고, 구간 안에서 엔트리마다 확인만 됩니다.
3. **인덱스에 없는 칼럼은 테이블 필터.** 정비상태는 ROWID로 테이블을 읽은 뒤 Id 2에서 걸러집니다.
4. **세 층의 건수 감소 지점이 다릅니다.** 인덱스 단계 8,400건과 테이블 단계 후 2,100건의 차이가 곧 테이블 필터의 효과입니다.

📌 한 줄 정리: 선두 등치(정비소코드)와 첫 범위(접수일자)까지가 액세스 조건이고, 범위 뒤 정비구분은 인덱스 필터, 인덱스에 없는 정비상태는 테이블 필터라, Card가 8,400에서 2,100으로 줄어듭니다.
