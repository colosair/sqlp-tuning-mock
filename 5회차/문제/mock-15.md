## 문제 15

### 문제

상여지급 마감 배치는 사원별 성과 집계를 상여 테이블에 반영한다. 아래 (가)는 수정 가능 조인 뷰(updatable join view)를 통한 UPDATE이고, (나)는 같은 목적을 MERGE로 처리한 문장이다. 사원.사원번호는 사원 테이블의 PK이며 상여.사원번호는 사원을 참조한다. 두 문장의 동작과 조건에 대한 설명으로 가장 적절하지 <u>않은</u> 것은?

#### [아 래]

```sql
-- (가) 수정 가능 조인 뷰를 통한 UPDATE
UPDATE (
    SELECT b.상여금액, s.기준급
    FROM   상여 b, 사원 s
    WHERE  b.사원번호 = s.사원번호
)
SET 상여금액 = 기준급 * 0.15;

-- (나) 같은 반영을 MERGE로
MERGE INTO 상여 t
USING 성과집계 s
ON (t.사원번호 = s.사원번호)
WHEN MATCHED THEN
    UPDATE SET t.상여금액 = s.산정액
WHEN NOT MATCHED THEN
    INSERT (사원번호, 상여금액) VALUES (s.사원번호, s.산정액);
```

### 선택지

① (가)에서 UPDATE 대상 칼럼(상여금액)이 속한 상여는 조인에서 키가 보존되는(key-preserved) 테이블이어야 한다. 사원.사원번호가 PK라 상여 한 행에 사원 한 행만 대응하므로, 상여가 key-preserved가 되어 상여금액 수정이 허용된다.

② (나)의 MERGE는 한 문장으로 대상(t)에 매칭 행이 있으면 UPDATE, 없으면 INSERT를 수행하며, 매칭 여부는 ON 절 조건(`t.사원번호 = s.사원번호`)으로 판정한다.

③ (가)의 조인 뷰에서는 key-preserved가 아닌 사원의 칼럼(기준급)도 조인에 참여했으므로 함께 UPDATE할 수 있고, (나)의 MERGE는 WHEN MATCHED와 WHEN NOT MATCHED 두 절을 반드시 함께 두어야만 실행된다.

④ (가)가 성립하려면 조인 후에도 상여의 사원번호가 유일해야 한다. 만약 사원 쪽 사원번호가 유일하지 않으면 상여 한 행이 여러 사원 행과 겹쳐 어떤 값으로 갱신할지 모호해지므로, 조인 뷰 UPDATE가 거부된다.

---

### 정답 — ③

### 왜 ③인가

수정 가능 조인 뷰의 핵심 규칙은 **key-preserved 테이블의 칼럼만 수정할 수 있다**는 것입니다. key-preserved란 조인 결과에서도 그 테이블의 각 행이 최대 한 번만 나타나 원래의 유일성이 보존되는 쪽을 말합니다.

```text
(가) 상여 b  ⋈  사원 s   ON b.사원번호 = s.사원번호
     사원.사원번호 = PK(유일)  →  상여 한 행에 사원 한 행만 매칭
     ⇒ 상여 = key-preserved(수정 가능),  사원 = 비보존(수정 불가)

(나) MERGE : WHEN MATCHED / WHEN NOT MATCHED 는 각각 선택적
     둘 중 하나만 써도 유효 (UPDATE만, 또는 INSERT만 하는 MERGE도 가능)
```

③은 두 군데를 뒤집었습니다. 첫째, 조인 뷰에서 수정할 수 있는 것은 **key-preserved 테이블(상여)의 칼럼뿐**이며, 비보존 쪽인 사원의 기준급은 조인에 참여했어도 UPDATE 대상이 될 수 없습니다. 둘째, MERGE의 `WHEN MATCHED`와 `WHEN NOT MATCHED`는 **둘 다 선택적**이라 하나만 두어도 실행됩니다 — UPDATE만 하는 MERGE, INSERT만 하는 MERGE도 정상입니다. ③은 "비보존 칼럼도 수정 가능"·"두 절을 반드시 함께"라는 정반대 진술을 겹쳐 놓았습니다. 그래서 부적절한 것은 ③입니다.

①은 상여가 key-preserved가 되는 근거(사원.사원번호 PK)를, ②는 MERGE의 매칭·분기 동작을, ④는 유일성이 깨지면 UPDATE가 모호해져 거부되는 이유를 옳게 서술합니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ○ | 사원.사원번호가 PK라 상여 한 행에 사원 한 행만 대응하므로 상여가 key-preserved입니다. 그 칼럼(상여금액)의 수정이 허용됩니다 |
| ② | ○ | MERGE는 한 문장으로 ON 조건 매칭 시 UPDATE, 미매칭 시 INSERT를 수행합니다. (나)의 구조 그대로입니다 |
| ③ | **✗** | 비보존 테이블(사원)의 기준급은 수정 대상이 될 수 없고, MERGE의 두 WHEN 절은 각각 선택적이라 하나만 둬도 실행됩니다 — 양쪽 다 반대 진술입니다 |
| ④ | ○ | 사원번호의 유일성이 깨지면 상여 행이 여러 행과 겹쳐 갱신값이 모호해지므로, key-preserved 조건 위반으로 UPDATE가 거부됩니다 |

---

## ✅ 이 문제의 핵심

1. **수정 가능 조인 뷰는 key-preserved 테이블의 칼럼만 수정**할 수 있습니다. 비보존 쪽 칼럼은 조인에 참여해도 UPDATE 대상이 아닙니다.
2. **key-preserved의 조건은 조인 후 유일성 보존**입니다. 상대 테이블의 조인 키가 PK/유일해야 내 행이 한 번만 나타납니다.
3. **MERGE의 WHEN MATCHED·WHEN NOT MATCHED는 둘 다 선택적**입니다. 하나만 둔 MERGE(UPDATE만 또는 INSERT만)도 정상 실행됩니다.
4. **유일성이 깨지면 조인 뷰 UPDATE는 거부**됩니다 — 한 행이 여러 행과 매칭돼 갱신값이 모호해지기 때문입니다.

📌 한 줄 정리: 조인 뷰에서는 key-preserved 테이블의 칼럼만 수정할 수 있고 MERGE의 두 WHEN 절은 각각 선택적인데, ③은 "비보존 칼럼도 수정 가능·두 절 반드시 함께"라 정반대로 서술해 부적절합니다.
