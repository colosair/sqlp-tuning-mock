## 문제 10

### 문제

수강신청 테이블(약 4,100만 건)과 강좌 테이블(약 12만 건)을 조인하는 SQL의 실행계획이다. 수강신청에는 `수강_IX = (개설학기, 학과코드, 신청일시)`가, 강좌에는 기본키 `강좌_PK = (강좌ID)`가 있다. `개설학기 = '2026-2'`이면서 `학과코드 = 'CSE'`인 수강신청은 약 530건이다. 이 실행계획에 대한 설명으로 가장 적절한 것은?

#### [아 래]

```sql
SELECT e.신청번호, e.신청일시, c.강좌명, c.담당교수
  FROM 수강신청 e, 강좌 c
 WHERE e.개설학기 = '2026-2'
   AND e.학과코드 = 'CSE'
   AND c.강좌ID = e.강좌ID;
```

```text
| Id  | Operation                       | Name       |
|-----|---------------------------------|------------|
|   0 | SELECT STATEMENT                |            |
|   1 |  NESTED LOOPS                   |            |
|   2 |   TABLE ACCESS BY INDEX ROWID   | 수강신청     |
|*  3 |    INDEX RANGE SCAN             | 수강_IX     |
|   4 |   TABLE ACCESS BY INDEX ROWID   | 강좌        |
|*  5 |    INDEX UNIQUE SCAN            | 강좌_PK     |
```

### 선택지

① 이 NESTED LOOPS에서 반복 탐색 부담은 인너 강좌(약 12만 건)의 크기가 좌우하고, 드라이빙 수강신청은 `수강_IX`(Id 3)로 이미 약 530건까지 줄어 더 손댈 여지가 없다. 따라서 강좌 테이블을 줄이거나 `강좌_PK` INDEX UNIQUE SCAN(Id 5)을 재구성해 인너 탐색 비용을 낮추는 것이 반복 부담을 더는 핵심 처방이다.

② 드라이빙(선행)은 먼저 나온 수강신청(Id 2)이고, `수강_IX`(Id 3)로 좁힌 약 530건 각각에 대해 `강좌_PK` INDEX UNIQUE SCAN(Id 5)이 반복 수행된다. NL은 드라이빙 앞쪽부터 조인해 내려가므로 상위 일부만 필요할 때 첫 행을 빠르게 내는 부분범위처리에 유리하다.

③ Id 4 TABLE ACCESS BY INDEX ROWID 강좌가 인너를 한 번에 읽어 강좌ID로 정렬·적재한 뒤 Id 2의 수강신청 약 530건과 병합하므로, 수강신청 4,100만 건과 강좌 12만 건은 각각 한 번씩만 스캔되고 Id 5 `강좌_PK` INDEX UNIQUE SCAN도 한 차례만 수행된다. 반복이 없으니 인너가 커져도 조인 비용은 늘지 않는다.

④ 이 플랜의 드라이빙은 Id 4의 강좌이고 수강신청을 인너로 두어 `수강_IX`(Id 3)를 강좌 12만 건마다 반복 탐색하므로, 부분범위처리 이득은 인너 수강신청에서 뽑히는 건수가 많을수록 커진다. `개설학기='2026-2' AND 학과코드='CSE'`인 약 530건은 그 반복 탐색으로 누적된 결과다.

---

### 정답 — ②

### 왜 ②인가

NESTED LOOPS(Id 1) 아래 두 자식의 **위치**와 **접근 경로**를 읽습니다.

```text
Id 1  NESTED LOOPS
Id 2   TABLE ACCESS BY INDEX ROWID 수강신청   ← 먼저 오는 자식 = 드라이빙(선행)
Id 3    INDEX RANGE SCAN 수강_IX             ← 드라이빙 집합 축소 (530건)
Id 4   TABLE ACCESS BY INDEX ROWID 강좌      ← 나중 자식 = 인너(후행), 반복 수행
Id 5    INDEX UNIQUE SCAN 강좌_PK            ← 인너 접근 경로 (드라이빙 건마다 재실행)
```

NESTED LOOPS에서 **먼저 나열된 자식이 드라이빙(선행) 집합**입니다. 여기서는 수강신청이 `수강_IX`(Id 3)로 `개설학기='2026-2' AND 학과코드='CSE'` 약 530건까지 좁혀지고, 그 **각 행마다** 인너 강좌를 `강좌_PK` INDEX UNIQUE SCAN(Id 5)으로 반복 탐색합니다. 즉 인너 접근 횟수는 드라이빙 수강신청 건수(약 530)만큼이며, 강좌가 12만 건이든 120만 건이든 **반복 횟수 자체는 드라이빙이 결정**합니다.

```text
인너 반복 횟수 = 드라이빙(수강신청) 건수 = 약 530회
             ≠ 인너(강좌) 테이블 크기 12만
```

또한 NL은 드라이빙 앞쪽 행부터 하나씩 조인해 결과를 곧바로 흘려보내므로, 전체를 다 완성하지 않고도 **첫 행을 빠르게** 낼 수 있습니다. 그래서 상위 일부(예: 화면 첫 페이지)만 필요할 때 전체 결과를 만들지 않고 멈추는 **부분범위처리**에 유리합니다. ②가 드라이빙 지목·반복 구조·부분범위처리 이점을 모두 정확히 서술합니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | ✗ | 인너 12만 건, 드라이빙 530건이라는 수치는 맞지만 병목을 엉뚱한 요인에 결부했습니다. Id 5 `강좌_PK` UNIQUE SCAN의 반복 횟수는 인너 크기가 아니라 드라이빙 530건이 결정하고 UNIQUE SCAN 1회 비용은 인덱스 높이만큼으로 고정이므로, 강좌를 줄여도 반복 부담은 그대로입니다 |
| ② | **○** | 먼저 나온 자식 수강신청(Id 2)이 드라이빙이고, 530건 각각에 `강좌_PK` UNIQUE SCAN(Id 5)이 반복됩니다. NL은 앞쪽부터 조인해 부분범위처리에 유리합니다 |
| ③ | ✗ | 인너를 한 번에 읽어 정렬·적재한 뒤 병합하는 것은 소트 머지 조인의 서술입니다. Id 1이 NESTED LOOPS이고 플랜에 SORT JOIN도 HASH JOIN 노드도 없으므로, Id 5 `강좌_PK` UNIQUE SCAN은 한 차례가 아니라 드라이빙 530건마다 반복 수행됩니다 |
| ④ | ✗ | 드라이빙과 인너를 뒤바꿨습니다. NESTED LOOPS에서 먼저 나열된 자식 Id 2가 수강신청이므로 드라이빙은 수강신청이고, 530건은 반복 탐색의 누적이 아니라 `수강_IX`가 Id 3에서 한 번에 좁힌 드라이빙 집합입니다. 부분범위처리 이득도 인너 건수가 아니라 상위 일부만 필요할 때 커집니다 |

---

## ✅ 이 문제의 핵심

1. **NESTED LOOPS의 먼저 나열된 자식이 드라이빙(선행) 집합**입니다. 여기서는 수강신청(Id 2)이 드라이빙입니다.
2. **인너 접근은 드라이빙 건수만큼 반복**됩니다. `강좌_PK` UNIQUE SCAN(Id 5)이 수강신청 530건마다 재실행됩니다.
3. **반복 횟수는 인너 크기가 아니라 드라이빙 건수가 결정**합니다. 강좌가 12만 건이어도 조인 반복은 530회입니다 — 병목을 인너 크기로 오귀속하지 않도록 주의합니다.
4. **NL은 부분범위처리에 유리**합니다. 드라이빙 앞쪽부터 조인해 상위 일부만 필요할 때 첫 행을 빠르게 냅니다.

📌 한 줄 정리: NESTED LOOPS에서 위쪽 자식 수강신청이 드라이빙이고 530건마다 `강좌_PK` UNIQUE SCAN이 반복되며, 반복 횟수는 인너 강좌 크기가 아니라 드라이빙 수강신청 건수가 결정하고 NL은 부분범위처리에 유리합니다.
