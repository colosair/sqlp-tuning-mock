## 문제 19

### 문제

SQL Server에서 공연예매 현황 테이블의 공연회차 'S7' 행(초기 잔여좌석 = 20)을 두 세션이 아래 순서로 다룬다. TX1은 t1에서 잔여좌석을 6 줄이고(아직 커밋하지 않음), TX2는 t2에서 같은 조건의 SELECT로 (가)를 읽는다. 이후 t3에서 TX1이 ROLLBACK한다. TX2의 격리수준은 READ UNCOMMITTED이다. TX2가 t2에서 읽는 값 (가)와 그때 발생하는 현상에 대한 진단으로 가장 적절한 것은? (단, 발문에 없는 힌트·격리수준 조정은 하지 않았고, TX1의 감소분은 t3에서 그대로 롤백된다.)

#### [아 래]

```text
시각   TX1 (예매 반영, 미완결)                        TX2 (현황 조회, READ UNCOMMITTED)
----   ------------------------------------------   ------------------------------------
t1     UPDATE 공연예매 SET 잔여좌석 = 잔여좌석 - 6
       WHERE 공연회차='S7';   (→ 14, COMMIT 안 함)
t2                                                  SELECT 잔여좌석 FROM 공연예매
                                                    WHERE 공연회차='S7';   → (가) 읽음
t3     ROLLBACK;   (→ 20 복원)

초기 잔여좌석(S7) = 20
```

### 선택지

① TX2가 READ UNCOMMITTED라 t2에서 아직 커밋되지 않은 14를 읽어 (가)=14이며, TX1이 t3에서 롤백하므로 실제로 확정된 적 없는 값을 읽은 Dirty Read다. 격리수준을 READ COMMITTED 이상으로 올리면 t2는 커밋된 20을 보게 되어 이 현상이 사라진다.

② (가)=20이다. READ UNCOMMITTED는 공유 락을 걸지 않을 뿐 SELECT는 커밋된 값만 읽으므로, t2 시점에 TX1의 미커밋 14는 보이지 않고 t3에서 복원되는 값과 같은 20을 반환한다. 읽은 값이 확정값과 일치하므로 이상현상은 발생하지 않는다.

③ (가)=14인 것은 맞지만 이는 Non-Repeatable Read다. 초기 20이 t1의 UPDATE로 14가 되었고 t2가 그 달라진 값을 읽었으니 같은 행에서 20과 14라는 두 값이 관측된 셈이기 때문이며, 격리수준을 REPEATABLE READ로 올려야 사라진다.

④ TX2가 t2에서 락을 기다리지 않고 곧바로 S7 행의 14를 읽었다는 사실이 이 현상이 Dirty Read가 아님을 보여 준다. READ COMMITTED에서도 SELECT는 대기 없이 읽으므로, 대기 없이 읽혔다는 것만으로 t1의 미커밋 UPDATE와 무관한 정상 읽기로 보아야 한다.

---

### 정답 — ①

### 왜 ①인가

READ UNCOMMITTED는 다른 트랜잭션이 **아직 커밋하지 않은 변경분까지** 읽습니다. 그래서 TX1이 감소만 하고 커밋하지 않은 상태에서 TX2가 그 값을 읽고, 이후 TX1이 롤백하면 TX2는 실재하지 않았던 값을 읽은 셈이 됩니다 — 이것이 Dirty Read입니다.

```text
[ 타임라인 — 잔여좌석(S7) 초기 20 ]
  t1  TX1 UPDATE = 20 - 6 = 14      (미커밋)
  t2  TX2(RU) SELECT → (가) = 14    (커밋 안 된 값을 읽음)
  t3  TX1 ROLLBACK → 20 복원        (14는 확정된 적 없는 값 = Dirty Read)

[ 격리수준별 t2의 (가) ]
  READ UNCOMMITTED : (가) = 14   → Dirty Read 발생
  READ COMMITTED   : (가) = 20   → 미커밋 14가 안 보임 → Dirty Read 없음
```

READ UNCOMMITTED에서 (가)=14이고, TX1이 롤백해 그 값은 확정된 적이 없으므로 Dirty Read가 맞습니다. READ COMMITTED 이상이면 커밋된 값만 읽어 t2는 20을 보고 현상이 사라집니다. ①이 값·현상·격리수준 상향 효과를 모두 맞혔습니다.

②는 RU가 공유 락을 걸지 않는다는 참인 사실에서 "커밋된 값만 읽는다"로 건너뛰었고(실제로는 미커밋 14를 읽음), ③은 초기값 20과 t2의 단 한 번의 읽기를 재조회 2회로 오분류했으며, ④는 "락 대기 없이 읽음"이라는 RU·RC에 공통인 단서를 판별 근거로 삼은 오류입니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | **○** | RU라 t2에서 미커밋 14를 읽어 (가)=14, t3 롤백으로 확정된 적 없는 값을 읽은 Dirty Read이며, RC 이상이면 20을 봐 사라집니다 |
| ② | ✗ | 공유 락을 걸지 않는다는 대목은 맞지만, RU는 거기서 더 나아가 미커밋 변경분까지 읽습니다. t2가 보는 값은 t3에서 복원될 20이 아니라 TX1이 만든 14이고, 그래서 Dirty Read가 발생합니다 |
| ③ | ✗ | TX2는 t2에서 한 번만 읽었습니다. 20과 14가 관측됐다는 것은 초기값과 t2 읽기를 나란히 놓은 것일 뿐 TX2의 재조회가 아니므로, Non-Repeatable Read가 아니라 Dirty Read이고 RC만 되어도 사라집니다 |
| ④ | ✗ | "락 대기 없이 읽음"은 RU·RC에 공통이라 현상 판별 근거가 못 됩니다. RC였다면 대기 없이 읽되 값은 20이었을 것이므로, 대기 유무가 아니라 t1의 미커밋 14를 읽었는지가 Dirty Read를 가릅니다 |

---

## ✅ 이 문제의 핵심

1. **Dirty Read = 커밋되지 않은 변경분을 읽고, 그 트랜잭션이 롤백되어 실재하지 않았던 값을 읽은 현상**입니다. 여기서 (가)=14가 그 값입니다.
2. **READ UNCOMMITTED는 미커밋 변경을 읽습니다.** READ COMMITTED 이상은 커밋된 값만 읽어 Dirty Read를 막습니다.
3. **Dirty Read와 Non-Repeatable Read의 구분**: Dirty는 미커밋 값을 읽는 것(1회 읽기로도 성립), NRR은 재조회 사이 커밋된 변경으로 값이 달라지는 것(2회 읽기).
4. "락 대기 없이 즉시 읽었다"는 RU·RC 공통 단서라 이상현상의 판별 근거가 아닙니다.

📌 한 줄 정리: READ UNCOMMITTED는 미커밋 값을 읽으므로 (가)=14이고 TX1의 롤백으로 Dirty Read가 되며, "락 대기 없이 읽었다"는 공통 사실만으로는 현상을 가를 수 없습니다.
