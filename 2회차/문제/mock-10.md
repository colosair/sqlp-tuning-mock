## 문제 10

### 문제

인사평가 결과를 등급으로 환산하기 위해, 평가점수 테이블(약 640만 건)의 `평가점수`가 등급기준 테이블(등급 구간 8건)의 `하한점수`와 `상한점수` 사이에 드는지로 조인하는 SQL의 실행계획이다. 두 테이블 어디에도 조인에 쓸 인덱스는 없다. 이 실행계획에 대한 설명으로 가장 적절한 것은?

#### [아 래]

```sql
SELECT e.사번, e.평가점수, g.등급코드, g.등급명
  FROM 평가점수 e, 등급기준 g
 WHERE e.평가점수 >= g.하한점수
   AND e.평가점수 <= g.상한점수;
```

```text
| Id  | Operation             | Name       |
|-----|-----------------------|------------|
|   0 | SELECT STATEMENT      |            |
|   1 |  MERGE JOIN           |            |
|   2 |   SORT JOIN           |            |
|   3 |    TABLE ACCESS FULL  | 등급기준    |
|*  4 |   SORT JOIN           |            |
|   5 |    TABLE ACCESS FULL  | 평가점수    |
```

### 선택지

① 양쪽 집합을 각각 정렬(SORT JOIN)한 뒤 정렬 순서를 따라 병합(MERGE JOIN)하는 소트 머지 조인이며, 조인 조건이 범위(비등치)여서 해시 조인이 쓰일 수 없는 경우에 적합하다.

② Id 2·Id 4의 SORT JOIN이 등급기준 8건과 평가점수 640만 건을 각각 정렬하므로, 이는 정렬 결과를 해시 버킷에 적재해 탐침하는 해시 조인의 한 형태이고 Id 1 MERGE JOIN은 그 병합 단계다.

③ Id 2·Id 4의 SORT JOIN이 640만 건 평가점수까지 정렬하는 부하를 만들고 Id 3·Id 5에서 Full Scan까지 하므로, 이 방식은 등급기준 8건을 인너로 삼는 NL 조인보다 항상 느리다.

④ MERGE JOIN은 등치(=) 조인만 처리하므로, `평가점수 >= 하한점수 AND <= 상한점수`라는 범위 조건도 옵티마이저에 의해 실제로는 등치로 변환된 뒤 Id 4의 `*` 지점에서 평가된 것이다.

---

### 정답 — ①

### 왜 ①인가

MERGE JOIN(Id 1) 아래 두 자식의 **연산 종류**를 읽습니다.

```text
Id 1  MERGE JOIN                     ← 정렬된 두 스트림을 병합
Id 2   SORT JOIN → TABLE ACCESS FULL 등급기준   ← 왼쪽 입력을 정렬
Id 4   SORT JOIN → TABLE ACCESS FULL 평가점수   ← 오른쪽 입력을 정렬
```

두 입력이 **각각 독립적으로 TABLE ACCESS FULL로 읽힌 뒤 SORT JOIN으로 정렬**되고, 그 정렬 순서를 따라 MERGE JOIN이 두 스트림을 병합합니다. 이것이 소트 머지 조인의 표준 형태입니다.

조인 조건 `평가점수 BETWEEN 하한점수 AND 상한점수`는 **비등치(범위)** 조건입니다. 해시 조인은 해시 버킷을 등치(`=`)로만 매칭하므로 이런 범위 조인을 처리하지 못합니다. 반면 소트 머지 조인은 양쪽을 정렬해 두면 범위 비교로도 병합할 수 있어, 비등치 조인에서 유효한 선택지입니다. Id 4 SORT JOIN에 붙은 `*` 마커가 바로 이 범위 조인 조건이 평가되는 지점입니다.

그래서 ①이 이 플랜의 연산 구조(양쪽 독립 액세스 + 각각 정렬 + 병합)와 조인 조건 성격(비등치)을 모두 정확히 서술합니다.

- ②는 Id 2·Id 4가 양쪽을 정렬한다는 사실까지는 맞지만, 이 플랜에 없는 **HASH JOIN**을 끌어옵니다. 상위 노드는 Id 1 MERGE JOIN이고 해시 버킷 적재·탐침 노드가 없습니다.
- ③은 640만 건 정렬과 Id 3·Id 5의 Full Scan을 근거로 '정렬=비효율'이라 반사적으로 판단한 것인데, 조인 인덱스가 아예 없어 등급기준을 인너로 둔 NL은 반복 Full Scan을 하므로 오히려 더 나쁠 수 있습니다.
- ④는 조인 조건이 부등호 두 개라는 사실은 맞게 읽고도 MERGE JOIN을 등치 전용으로 착각한 것으로, SORT MERGE는 비등치 조인을 처리하는 대표적 방식이고 Id 4의 `*`는 그 범위 조건 평가 지점입니다.

### 오답 이유

| 선택지 | 판정 | 이유 |
|:-:|:-:|---|
| ① | **○** | Id 2·Id 4의 SORT JOIN이 양쪽을 정렬하고 Id 1 MERGE JOIN이 병합하며, 조인 조건이 BETWEEN(비등치)이라 해시 조인이 못 쓰이는 상황과 일치합니다 |
| ② | ✗ | Id 2·Id 4가 8건과 640만 건을 정렬하는 것은 맞지만 플랜에 HASH JOIN·해시 버킷 적재·탐침 노드가 없습니다. 상위 조인 노드는 Id 1 MERGE JOIN이며 SORT JOIN은 해시가 아니라 병합을 위한 정렬입니다 |
| ③ | ✗ | 640만 건 정렬과 Id 3·Id 5의 Full Scan은 사실이나, 두 테이블 어디에도 조인 인덱스가 없어 등급기준 8건을 인너로 둔 NL은 인너를 Full Scan으로 반복합니다. 정렬이 있다는 사실만으로 NL보다 느리다고 단정할 수 없습니다 |
| ④ | ✗ | 조인 조건이 `>=`·`<=` 두 개라는 관찰은 맞지만 이는 비등치이며, MERGE JOIN은 바로 이런 범위 조인을 처리하는 방식입니다. 등치로 변환된 적이 없고 Id 4의 `*`가 그 범위 조건 평가 지점입니다 |

---

## ✅ 이 문제의 핵심

1. **MERGE JOIN 아래 양쪽 SORT JOIN이면 소트 머지 조인**입니다. 두 입력을 각각 정렬한 뒤 순서대로 병합합니다.
2. **양쪽이 독립적으로 액세스**됩니다. 여기서는 두 테이블 모두 TABLE ACCESS FULL로 읽힌 뒤 정렬됩니다.
3. **비등치(범위) 조인은 해시 조인이 못 합니다.** 해시는 등치 매칭만 하므로 BETWEEN 조인에는 소트 머지가 유효한 선택입니다.
4. **정렬 노드가 있다고 무조건 비효율은 아닙니다.** 조인 인덱스가 없으면 NL의 반복 Full Scan이 더 나쁠 수 있습니다.

📌 한 줄 정리: MERGE JOIN 아래 두 SORT JOIN이 양쪽을 각각 정렬해 병합하는 소트 머지 조인이며, 조인 조건이 BETWEEN(비등치)이라 해시 조인이 못 쓰이는 상황에 적합합니다.
